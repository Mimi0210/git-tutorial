Git là gì — và 4 cách làm việc

Hiểu nền tảng trước khi mở bảng 9 tình huống

Git là hệ thống quản lý phiên bản (Version Control). Mỗi lần lưu có chủ đích gọi là commit — Git ghi lại ai đổi gì, lúc nào, và vì sao. Repo local trên máy; remote (GitLab / GitHub) để team đồng bộ, review và backup.

Git CLI

Nền tảng. Mọi GUI đều map về lệnh — biết CLI thì hiểu Git đang làm gì.

Cursor / VS Code

Source Control + Merge Editor ngay trong IDE — tiện khi đang code.

GitHub Desktop

GUI đơn giản, history dễ nhìn — phù hợp demo và thao tác hàng ngày.

Fork

GUI mạnh: rebase, cherry-pick, conflict — khi cần kiểm soát graph chi tiết.

Dùng GUI khi

  • Cần nhìn branch / history / conflict trực quan
  • Thao tác thường ngày: commit, push, tạo branch, discard
  • Demo hoặc training member mới

Dùng CLI khi

  • Cần chính xác, scriptable, hoặc lệnh GUI không expose đủ
  • Recovery nâng cao: reflog, filter, force-with-lease
  • Muốn hiểu / verify “Equivalent CLI” sau mỗi thao tác GUI

Nguyên tắcCLI là nền tảng. Biết bấm GUI mà không hiểu command tương ứng → dễ “sửa mù” khi gặp lỗi.

Trước khi reset / force push / amend

Checklist “vàng”

Hỏi đủ 5 câu trước mọi thao tác nguy hiểm

  1. 01
    Đang ở branch nào?

    git branch --show-current hoặc git status — đừng reset nhầm main.

  2. 02
    Thay đổi đã commit chưa?

    Uncommitted có thể mất hết với reset --hard / discard. Stash hoặc commit trước nếu còn cần.

  3. 03
    Đã push chưa? Có ai khác đang dùng branch không?

    Đã share → ưu tiên revert, tránh force push. Chưa share → reset an toàn hơn.

  4. 04
    Có cần backup branch không?

    Trước khi reset: git branch backup-… — giữ điểm quay lại nếu lỡ tay.

  5. 05
    File nhạy cảm đã lên remote chưa?

    .env, token, dump DB — nếu đã push: rotate secret ngay, rồi mới dọn history.

NhớĐọc state trước khi sửa: status → log → branch -vv → rồi mới reset / force.
